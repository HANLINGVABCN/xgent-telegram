# Web 全局搜索

入口：左侧「搜索对话名称和内容」、工作台菜单「全局搜索」、`Ctrl+F`（macOS 为 `Cmd+F`）。

默认范围是全部未删除对话，包含归档；不受侧栏当前日期、分组、置顶及模型上下文窗口限制。搜索本身是只读操作，不触发 AI，不变更 Telegram 当前对话。

- 支持对话名称、用户正文、AI 回复、工具结果、附件说明及已记录的文件名/路径。
- 中文直接匹配；英文忽略大小写，支持 Unicode 大小写折叠。`%`、`_`、引号、括号均按字面文本查询，不作为 SQL、正则或搜索运算符。
- 名称命中优先，消息命中按时间倒序；结果标出来源、消息类型、时间及命中片段。
- 点击消息定位精确的历史记录，不通过时间猜测；点击名称打开该对话。归档结果以只读方式浏览，不会自动恢复归档。
- 弹窗可按未归档/已归档、对话名称/用户/AI/工具筛选。每批 30 条，可持续加载更多；不会把总结果悄悄截为 30 条。输入框向下键进入结果，上下键移动，Enter 打开，Esc 关闭。
- 查询会保留聊天草稿。输入新关键词立即废弃旧请求；加载失败保留关键词及已有结果，可重试。关闭弹窗或退出登录取消查询。

搜索的是数据库内保留的可见历史，不是磁盘全文检索：不会打开 PDF、压缩包或任意服务器文件，也不会把附件的二进制/Base64 编码当正文。内部按钮操作、配置管理审计记录、配置附件及隐藏元数据不作为搜索内容返回。

实现不依赖额外数据库、FTS 扩展或重新导入历史数据。`GET /api/workbench/global-search` 使用已登录 Web 身份，读取独立只读 SQLite 连接；支持 `q`、`archive`、`kind`、`limit`、`cursor`。游标绑定关键词及筛选，按稳定消息 ID 分页，并固定消息快照上界，避免分页期间新消息造成重复。响应只含摘要和来源标识，不返回原始元数据或附件数据。

每个关键词最多 200 字符，以保护交互查询；没有历史消息数量截断。长时间查询有明确超时提示，不以空结果冒充成功。
