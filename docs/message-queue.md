# 普通文本待发队列

Telegram、Web、CLI/TUI 可在任务执行中继续提交**普通文本**。附件、斜杠命令、配置值和 ask 密钥/字段输入不进入队列；Telegram 长文本仍先完成原有拼接。发送成功表示已持久保存，不表示已经调用模型。

## 何时送入 AI

- 同会话：在当前一批工具操作结束、下一次模型调用前，按入队顺序取出所有可发送文字。完整工具结果在前，各条用户消息独立放在后面，不与工具输出拼成一段，不重复读库丢失多模态上下文。
- 没有工具续接：自然结束后作为正常新提问处理。不同对话等待同一个全局执行位，按最早可发送队首选对话，再取该对话的批次。切换查看不改投，始终不并发执行模型任务。
- 有待发文字时，`over-x` 不省略工具回传；没有待发文字时行为不变。等待 ask 表单时不绕过表单；提交后随表单答案接入，取消表单则保留队列并暂停。
- 本批消息全部追加一次，即使条数超过普通历史深度也不裁掉。历史深度、tokens 统计、既有工具快照及自动压缩策略不改。

## 取消、编辑与暂停

- Web 在输入区上方显示队列，默认三条，可展开。生成时发送按钮用于排队，停止按钮仍可用。每条有「❌ 取消」「编辑」；编辑先取消待发，再把原文放到原对话草稿前，以空行分隔，保留已有草稿。重发排在队尾。
- Telegram 原生待发输入有一个 Bot 回执，带「❌ 取消」，状态编辑原回执；`/queue` 查看当前会话各端队列、取消、继续。其他端入队不额外广播回执。Bot 不能修改用户原消息。
- TUI 输入区旁支持点击取消、编辑、继续；行式终端使用 `/queue`、`/queue cancel <id>`、`/queue edit <id>`、`/queue resume`。交互式输入取回预填；无交互编辑能力时输出原文，不代替用户再次发送。
- 只有尚未领取的消息能撤回。取消和领取在数据库事务中竞争，领取先成功会明确提示「已接入本轮，无法撤回」。队列保存失败不清草稿。请求 ID 用于重试去重，不按文字去重。
- 主动停止或不能继续的模型/运行异常会暂停**所有现存待发队列**。工具返回非零但仍可交给 AI 处理不算整轮异常。继续按钮或命令只恢复所选对话；新发文字不隐式恢复暂停队列。
- 网页刷新不暂停。来源进程退出/崩溃后，未领取内容保留暂停；新开另一个终端不影响存活进程。已领取但完成情况不明的消息标记中断，绝不自动重放可能已执行的操作。
- 归档暂停，恢复归档不自动发送；重置/压缩后旧 generation 的文字仍可取回重发，不能直接恢复。永久删除对话同时清理对应队列。

## 接口和实现

`POST /api/chat` 保留原字段，普通文本支持 `request_id` 和 `generation`，响应增加 `queued`、队列 `id`、`status`、`revision`；已有管理状态仍走原状态机。管理输入只保存不含原文/密钥的请求回执，重试不会被重解释为普通聊天。

- `GET /api/queue?conversation_id=…`：当前队列与版本。
- `POST /api/queue/cancel`、`/api/queue/edit`：`conversation_id`、`generation`、`id`、`revision`；编辑必须带 `request_id`，重复请求返回同一次取回结果。
- `POST /api/queue/resume`：`conversation_id`、`generation`、队列 `revision` 和 `request_id`，防止过期按钮恢复后来暂停的队列。
- 通过现有事件连接发布 `queue_state` 修订通知；客户端只读取自己的视图，队列更新不重建历史或强制跳到底。正式消息含 `queue_id` 关联，替代待发显示而非复制一遍用户气泡。

SQLite 队列与正常历史分开；取消/未接入内容不进入模型、普通导出或压缩。领取与正式用户记录在同一事务提交。新回合由队首的存活来源进程派发，续接保留当前进程/路由；包含 Telegram 原生提问的批次保留 Bot 回复。其他投递仍经过原异步出站队列。
