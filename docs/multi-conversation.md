# 轻量多会话：使用与实现说明

## 更新简介

网页交互已改为以对话列表为主：桌面左侧最近对话、手机抽屉、搜索、逐条操作和归档撤销。旧左上角命令菜单及展开式管理表单已删除，聊天区不再承担会话管理表单。

本次增加新建、切换、重命名、归档和恢复会话。一件任务拥有一份独立上下文，但仍复用原来的模型调用、Agent 执行、Telegram/Web/CLI 桥接和同一个 SQLite 数据库，不建立多套执行引擎。

三端同步“当前查看的会话”。正在执行的任务保留启动时的会话归属；切换不会中断任务，也不会把旧回复、附件或后台结果混入新会话。

## 使用方式

- Telegram 的普通回复与 `/start` 等菜单命令都带 `🗂 对话名 · 短编号`，默认会话继续显示 `global` 短编号。点到其他会话或旧上下文的按钮时，只弹出原因并结束按钮转圈，不执行动作、不修改原卡片、不发送额外聊天消息。
- 压缩结束后，Telegram 与 Web 都会收到已有实际用量的 Token 提示（输入、输出、缓存命中和生成速度）；没有返回用量时不伪造数字。提示只作展示，用量统计只保存一次。

- Telegram、CLI：`/chats` 打开管理菜单，`/new [名称]` 新建并切换。重命名、归档、恢复通过共用菜单完成。
- Web：桌面端左侧“新对话”下方直接显示最近对话列表，支持搜索、时间分组和一键切换；手机端点标题旁的“对话记录”打开抽屉。每条对话旁的 `⋯` 可重命名或归档，归档提示提供撤销，已归档列表提供直接恢复。
- 重命名使用独立弹窗，自动刷新不会覆盖正在输入的名称；可以重命名非当前对话。未命名对话会用首条实际消息生成简短标题，不额外调用模型，已有自定义名称不会被覆盖。
- 切换仅改变查看位置，不再把对话列表重新排序；排序按消息活动时间。输入草稿和待发送附件按会话保留；另一端切换后，旧请求不会静默改投。
- 已删除网页左上角的旧命令菜单按钮、命令搜索入口、旧侧栏与遮罩。需要 Bot 命令时，仍可用输入框旁的命令入口、`/` 提示或 `Ctrl/⌘ K`。
- `/clear_memory`、`/compress`、`/export` 和普通历史搜索只处理当前会话。
- 正在执行时可以切换查看；新用户请求提示忙碌，不进入历史。一个 Telegram 相册组作为同一次已接收的请求处理，组内分批到达的附件仍归原会话。
- 归档不删除数据、不停止既有定时任务。归档当前会话后切到最近活动的未归档会话；没有可选项时自动创建空白会话。
- 已归档会话的定时任务继续运行，结果保留在原会话。需要继续手工对话时先恢复。

## 隔离与共享范围

| 按会话隔离 | 继续全局共享 |
| --- | --- |
| 聊天记录、工具上下文与消息搜索 | 模型提供商和模型选择 |
| 附件自动上下文及生成图片关联 | 人设、提示词、Skill |
| 压缩链、摘要和导出 | 手工“用户记忆”文件 |
| 待回答表单、文本拼接、相册归属 | 文件工作目录、全局用量统计 |
| 进程内的会话私密变量 | 原有后台 Shell 与定时命令能力 |

私密变量不再写入进程全局环境；仅向对应会话启动的子进程注入。变量仍不落盘，不新增跨进程密钥同步服务。文件目录和操作权限仍共享，因此这不是安全沙箱或多租户权限隔离。

## 实现要点

1. **分开查看位置和操作归属。** `current_chat_id` 是三端同步选择；`ConversationScope` 是操作开始时绑定的不可变身份。入口在第一条记录或附件关联之前绑定，内部尽量保留原函数签名。
2. **集中改数据访问。** 复用 `chat_sessions` 和 `global_messages.session_id`，统一约束消息、附件、UI 历史、压缩、搜索和清空。普通配置不按会话复制。
3. **复用版本检查。** 每个会话保存自己的 `generation`，版本号由全局递增序列分配。切换不换版；清空或成功压缩只推进目标会话。旧任务和旧按钮不能恢复已失效的数据。
4. **仍只有一个执行槽。** 进程内锁之外使用标准库实现的操作系统文件锁，覆盖 CLI 与服务端。数据库事务不跨模型等待；进程退出后系统释放文件锁。
5. **消息流携带身份。** Web 帧、CLI 中继与持久出站队列保存会话、版本及回合标识；工作线程重放原作用域，不读取新的“当前会话”。CLI 原有 `session_id` 仍表示中继进程，不混用为逻辑会话 ID。
6. **停止绑定具体回合。** 旧停止按钮不能停止后来启动的任务。清空先请求停止，再原子推进版本；不等待卡住的下载完成，旧结果由版本校验拒绝，执行槽直到旧回合真正退出才释放。

核心组件为 `xgent_app/conversations.py` 与 `xgent_app/conversation_store.py`。现有数据库、入口和消息桥接做针对性接线，Agent 协议与工具执行流程不重新实现。

## Web 接口变化

- `GET /api/workbench/conversations`：会话列表、当前会话、修订号与运行状态。
- `POST /api/workbench/conversations/{create,switch,rename,archive,restore}`：会话管理；非新建操作显式提供 `id`。
- 聊天、上传、按钮、命令及会话相关操作携带 `conversation_id`；过期选择返回冲突提示，不能自动改投。
- 停止请求携带 `run_id`，可同时携带所属 `conversation_id`。
- 历史、游标、实时快照按会话和版本匹配。切换重载目标历史，其他会话的输出不插入当前聊天区。

## 升级、备份与回退

1. 停止服务端以及所有 CLI 进程，避免新旧代码混跑。
2. 首次新版本启动自动生成数据库旁的 `*.pre-conversations-v1.sqlite3` 备份；使用 SQLite 备份 API，包含 WAL 中已提交的数据。
3. 在事务中迁移旧消息、附件关联、UI、压缩及任务归属到 `global_memory` 默认会话；不推断旧话题、不移动附件原件。
4. 迁移带版本标记，重复启动不会合并新会话或重置当前选择。
5. 回退旧程序必须恢复升级前数据库；只替换代码不安全。升级后的新增会话不在旧备份中，回退前另行完整备份。

`.turn.lock` 是固定锁文件，不能通过删除文件来“解锁”；正常停止或进程退出会释放操作系统锁。

## 验证覆盖

专项测试覆盖：两会话读写与压缩隔离、全局唯一版本、陈旧写入拒绝、旧数据库迁移、跨进程互斥与崩溃释放、归档任务回流、SSE/中继作用域、旧停止事件、同名私密变量、浏览器双标签同步以及独立草稿恢复。

测试使用临时数据库和模拟模型，不启动真实 Telegram 调用，也不迁移用户现有运行数据。
