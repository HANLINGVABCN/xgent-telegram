# 对话独立执行、备份全选与消息回填

本次更新解决五个具体问题：输入框设置重复提供思考等级、不同对话共享执行锁、导入全选遗漏高级项、分支按钮缺少明确文字，以及撤回或取消后没有取回消息原文。

## 改动后的行为

1. 输入框保留独立的思考等级选择，手机端也直接显示。设置按钮提供流式输出和 Agent 自动执行开关。Web、Bot、CLI 统一采用可展开的紧凑预览，删除非折叠模式及切换入口；旧客户端或配置写入会归一到当前显示方式。
2. 对话 A 等待模型或命令时，对话 B 可以启动自己的回合。同一对话仍串行执行，跨进程文件锁防止重复接纳。运行任务、停止事件、回复订阅、命令环境及队列分别归属各自对话；停止、失败或删除只影响目标对话。
3. 导入全选覆盖所有可导入部分，包括高级项。完整数据库或环境文件已包含的分项同步显示勾选，并标明“已包含”；提交时去重。压缩包列表提供全选、全不选、已选数量及批量删除；刷新保留仍存在的选择，复选框不会触发扫描。
4. 消息旁的分支按钮只替换为新的分叉箭头图标，保留原按钮尺寸与样式；“分支到新聊天”仅作悬停与无障碍说明。分支仍只复制对话上下文。
5. 撤回成功后将对应用户消息放回原对话输入框。待发消息保留取消、编辑两个按钮，两者都取回原文，以空行分隔保留已有草稿。切换对话、丢失响应和重试均不会回填错对话或重复插入。

普通对话仍共享项目文件目录；并行执行不代表文件系统隔离。涉及整份文件恢复的维护操作仍排斥正在执行的回合；纯消息撤回只占用目标对话的执行槽。

## 单行执行预览与紧凑尾注

Web 统一采用已确认的单行执行预览。默认只有协议名、实际状态和一行内容，例如 `run-x 已运行 uptime` 或 `file-x 已运行 workspace/report.md`；没有代码框或复制工具栏。点开后显示 12px / 17px 的完整代码块，并提供换行、正文复制、完整协议复制、执行信息及完整输出等适用操作。按钮和文字选择不会误触发折叠。

输出成功用绿点、失败用红点；运行中、停止和无法确认的历史记录使用对应文字或中性标记。源回复的协议状态会随实际执行更新并保存，刷新历史沿用已记录的事实。

Token 使用 `↑ 4,110 · ↓ 86 · cache 3,660 · 约 1 秒` 形式的小字尾注。回答时间和生成时使用的提供商、模型移到尾注最左侧，与 Token 保持约几个空格的间距，执行汇总紧随其后。同一条用户消息引出的多轮回复仅在第一条显示 XGent 头像与名称；旧历史缺少轮次标识时按用户消息分组，翻页、实时定稿和刷新保持一致。复制、引用、朗读和分支图标放在同一尾部区域右侧；手机默认只有复制、分支和“更多”。系统提示移除通用复制、引用、朗读操作、标题与空时间行，但保留错误、停止、表单和重试等必要内容。

尾注里的时间是本轮模型响应耗时。新回复保存耗时并用于实时显示及刷新历史；旧记录缺少该字段时明确显示“耗时未记录”。用量详情里的“首字延迟：未采集”是另一个指标，当前没有采集，不能作为本轮响应耗时。

修正停止后无条件写入“操作已完成”的路径；停止的本轮只记录准确的停止终态，已完成的其他轮次和实际结果保留。上传进度也已适配新的尾部布局，不影响附件与服务器上传的发送流程。

## 升级

数据库版本升至 schema v7，使用按对话保存的 `conversation_runs` 运行记录。升级前停止服务端和所有 CLI，并一起更新代码；现有迁移机制自动备份数据库。回退时同时恢复升级前数据库，旧程序会拒绝较新的数据库版本。
