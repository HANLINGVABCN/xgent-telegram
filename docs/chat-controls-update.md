# 消息类型迁移、备份分组与停止展示

本次更新让实时消息、刷新历史和模型上下文按同一份固定类型处理，隔离 Bot／CLI 的表单录入提示；备份选择合并为互不重叠的组并排除服务器资产配置。已有的对话独立执行、单行代码预览、分支图标和消息回填继续保留。

## 启动时迁移消息类型

数据库升级到 schema v8。服务端或 CLI 第一次启动时，先保存原数据库，再在事务中补齐每条历史消息的用途、说话者、可见端、是否进入模型上下文以及表单归属。迁移只更新元数据，保留原始正文、消息 ID、时间和会话归属；异常会回滚且不推进版本号，重试可继续，成功后再次启动不重复迁移。

旧的“请填写”“已填入”、可明确关联的字段输入和自动表单回执只在这次迁移中识别。运行时与刷新历史按保存的类型读取，新增普通消息即使使用相同文字也仍是普通消息。消息用途与模型角色分开：表单完整答案只给模型；字段录入通知只在原 Bot／CLI 端出现；原表单、草稿状态和正常回答继续同步。待投递队列也在启动迁移中补齐类型，避免重放旧消息时重新污染界面。

选择性导入对话或队列后，即使目标数据库已是 v8，也会在下一次启动先保存 `.pre-message-policy-<导入编号>.sqlite3`，完成一次消息类型迁移，再启用历史读取和投递。这样旧备份里的消息也有固定类型，无需在运行期间兼容判断。

## 改动后的行为

1. 输入框保留独立的思考等级选择，手机端也直接显示。设置按钮提供“前台流式、后台流式、非流式”三个回复方式选项与“Agent 模式”开关。三个选项互斥，流式开关与输出风格在一次事务中保存；失败时不留下半套配置。Web、Bot、CLI 统一采用可展开的紧凑预览，删除非折叠模式及切换入口；旧客户端或配置写入会归一到当前显示方式。
2. 对话 A 等待模型或命令时，对话 B 可以启动自己的回合。同一对话仍串行执行，跨进程文件锁防止重复接纳。运行任务、停止事件、回复订阅、命令环境及队列分别归属各自对话；停止、失败或删除只影响目标对话。
3. 备份导出与导入使用相同的 7 组独立选项：连接与应用配置、对话与记忆、提示词与私有技能、任务与统计记录、工作区与附件、命令完整输出、待发送队列与运行状态。全选选中全部可用组，不再自动取消其他选项。所有新备份排除 `server_assets/`；压缩包列表保留全选、全不选、已选数量与批量删除。
4. 消息旁的分支按钮只替换为新的分叉箭头图标，保留原按钮尺寸与样式；“分支到新聊天”仅作悬停与无障碍说明。分支仍只复制对话上下文。
5. 撤回成功后将对应用户消息放回原对话输入框。待发消息保留取消、编辑两个按钮，两者都取回原文，以空行分隔保留已有草稿。切换对话、丢失响应和重试均不会回填错对话或重复插入。

普通对话仍共享项目文件目录；并行执行不代表文件系统隔离。涉及整份文件恢复的维护操作仍排斥正在执行的回合；纯消息撤回只占用目标对话的执行槽。

## 单行执行预览与紧凑尾注

Web 统一采用已确认的单行执行预览。默认只有协议名、实际状态和一行内容，例如 `run-x 已运行 uptime` 或 `file-x 已运行 workspace/report.md`；没有代码框或复制工具栏。点开后显示 12px / 17px 的完整代码块，并提供换行、正文复制、完整协议复制、执行信息及完整输出等适用操作。按钮和文字选择不会误触发折叠。

输出成功用绿点、失败用红点；运行中、停止和无法确认的历史记录使用对应文字或中性标记。源回复的协议状态会随实际执行更新并保存，刷新历史沿用已记录的事实。

`run-x` 在等待实际命令进程之前先发送“执行中”结果块，下面显示“❌ 停止回答”按钮，AI 生成中的按钮使用同样文字。按钮请求停止对应运行，保留已产生结果；命令结束后原地更新为绿点“输出”或准确的停止／失败状态。进行中使用可刷新快照，完成时关联同一条历史记录，不重复创建输出块。停止终态与汇总也关联同一条记录，实时与刷新后都显示一次。输入框停止按钮仍可使用。

Web 的 `ask-x` 改为原地填写表单，自定义答案、文本题和密钥题都有专属输入字段；单选、多选即时显示对号。普通草稿自动保存并在刷新时恢复，切换选项只更新草稿，提交才恢复原有的 Agent 多模态上下文。表单与历史消息建立关联，刷新后仍显示未提交表单；处理后保留已提交／已取消状态。完整性、版本和会话归属在服务端校验，避免重复提交或误填其他对话。

密钥明文不进入模型、历史记录或浏览器草稿存储；服务端仅保存录入状态。Bot、CLI 保留适合各自界面的文本录入入口，选中项统一显示对号。浏览器刷新保留等待中的表单；服务进程重启后无法恢复原来的内存多模态上下文时，旧表单明确显示失效，不能用缺失上下文继续执行。

Bot 的自定义和密钥录入统一交给创建原表单的投递对象更新，保留逻辑消息 ID 与 Telegram 原生消息 ID 的映射；不再用本次输入的原生 Bot 误编辑逻辑 ID，也不再在更新失败后新发整张表单。Web 只更新原表单的历史关联，CLI 全屏原地更新原表单菜单；普通终端无法重绘时只给简短更新提示。

`[用户已提交表单]` 开头的自动答案汇总作为模型续轮上下文保留，实时、刷新和 CLI 历史都不再显示为另一条用户消息。新记录使用明确的表单回执标记，已有的同格式自动汇总也在历史展示中隐藏；普通聊天中的“保证”“测试”等文字仍正常保留。

表单字段录入与普通聊天分开：Bot、CLI 的“请填写”“已填入”“密钥已录入”等录入引导只在对应输入端显示，不进入 Web 或持久化菜单。字段填写值只修改表单草稿，提交时才组装模型答案，不单独形成用户气泡。已有录入引导在历史中隐藏；旧字段文本只有被准确的表单提示与确认消息包围时才隐藏，跨页和来源定位沿用相同规则，不按“测试”等短词全局过滤。

浏览器本地仅保留尚未保存的字段草稿；保存成功后移除本地缓存，刷新时按服务器 revision 处理，避免旧的已保存内容挡住 Bot 更新。Web 原表单实时显示 Bot 填写的答案及密钥录入状态，提交前后不出现输入端的额外提示或字段消息。

回复尾注与输出之间压缩间距。本轮输出之后、下一轮回答之前，恢复一次 `Agent 第 N 轮 · K 个操作`，字体与 Token 尾注一致（11px / 17px），不显示大标题或通用消息操作栏。已停止或失败的轮次仍保留真实终态，不补写成功轮次；原始状态记录保持原样，实时显示与刷新历史使用同一简洁文字。

生成占位保留“前台流式输出中…”“后台流式输出中…”“非流式输出中…”，不再统一替换为“思考中”。后台流式的已生成字数继续更新；第二轮及后续轮的生成占位仍归类为 AI 回复，不会被当成上一轮工具输出。

Token 使用 `↑ 4,110 · ↓ 86 · cache 3,660 · 约 1 秒` 形式的小字尾注；上游没有提供缓存量时显示 `cache 0`，详细统计保留原始数据。回答时间在尾注最左侧，与 Token 保持约几个空格的间距，执行汇总紧随其后。实际提供商与模型移到本轮首个 XGent 头像旁；同一次连续 Agent 执行使用开始时选定的模型，中途切换仅影响下一次新请求。生成占位不重复显示底部时间或模型，系统提示和菜单不再显示“模型：历史记录未记录模型”。

同一条用户消息引出的多轮回复仅在第一条显示 XGent 头像与名称；优先按轮次或运行 ID 分组，旧历史缺少身份字段时按用户消息分组。排队消息在安全接入点加入同轮，上一轮的 Agent 轮次行先落库和显示，再接入并显示排队消息，刷新历史保持相同顺序。翻页和实时定稿不重复头像。复制、引用、朗读和分支图标放在同一尾部区域右侧；手机默认只有复制、分支和“更多”。系统提示移除通用复制、引用、朗读操作、标题与空时间行，但保留错误、停止、表单和重试等必要内容。

Web 的“❌ 停止回答”按钮从当前对话的实时生成帧和运行状态获得目标运行 ID；AI 回复和命令输出使用同样文字。停止请求绑定实际运行 ID，旧回合的完成或延迟帧不能停止新任务，也不会让已经结束的任务重新出现停止按钮。

尾注里的时间是本轮模型响应耗时。新回复保存耗时并用于实时显示及刷新历史；旧记录缺少该字段时明确显示“耗时未记录”。用量详情里的“首字延迟：未采集”是另一个指标，当前没有采集，不能作为本轮响应耗时。

修正停止后无条件写入“操作已完成”的路径；停止的本轮只记录准确的停止终态，已完成的其他轮次和实际结果保留。上传进度也已适配新的尾部布局，不影响附件与服务器上传的发送流程。

## 升级

数据库版本升至 schema v8，保留按对话保存的运行记录并迁移固定消息类型。升级前停止服务端和所有 CLI，并一起更新代码；启动时生成原数据库备份，v7 数据库的备份名为 `<数据库名>.pre-conversations-v8.sqlite3`。回退时同时恢复升级前数据库，旧程序会拒绝较新的数据库版本。

## 验证

- 启动迁移覆盖 v7 → v8、原数据库备份、正文／ID／时间不变、异常回滚、重试和重复启动；旧对话分项导入 v8 数据库后也先迁移再读取。
- 固定类型覆盖 Web 实时／刷新历史、模型上下文和 CLI 待投递队列。普通用户或 AI 回复包含“请填写”“Agent 已完成”等字样时仍按聊天消息显示。
- 真实 Python 命令进程与 Chromium 覆盖三种回复方式、生成中与命令输出的停止按钮、执行中刷新、停止后的进程退出，以及同一条输出、停止提示和汇总在实时／刷新后保持一致。
- 备份使用真实 SQLite 分项、ZIP／TAR.GZ／TAR.XZ 和选择性恢复，验证新备份排除服务器资产且导入不会删除目标已有资产；7 组选择、全选、上传扫描和批量删除在桌面／手机浏览器验证。
- 18 个 sections 完整性、Python 编译、JavaScript 语法、5 个 Shell 脚本语法和 Ruff 错误检查通过。完整 pytest 回归使用短临时目录运行。
