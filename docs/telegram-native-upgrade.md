# Telegram 原生能力接入进度

## 第一阶段：原生表格、富文本和草稿

Bot 的 AI 正文在 Telegram 出口使用 Rich HTML：表格保留表头、对齐、链接、强调、行内代码和转义竖线；默认紧凑显示。超过 20 列按列分组，保留首列；长表续段保留表头，正文和代码安全分段。标题、列表、引用、公式及脚注也使用原生格式。

模型原文、SQLite 内容、Web 和 CLI 展示不经过这份 Telegram 转换。工具仍逐条输出，保留原有 50 行／3200 字符预览；首行按真实状态显示协议名和状态点，存档在折叠块末尾。

前台流式使用同一个原生草稿 ID；草稿只有临时预览，不绑定正式消息 ID、不进入持久补发。后台流式和非流式保留各自状态，结束后发送完整正文。草稿超出一条消息的预算时预览当前末段，定稿保留全部分段。

生成期间保留一条紧凑状态消息和“❌ 停止回答”，关闭 Telegram 自带停止按钮。停止请求同时绑定运行与阶段，已结束阶段不能停止后续操作；结束后清理状态。连续多轮仍只在最终回复末尾附一次详情，使用最后一轮的模型、生成时间、耗时和 Token。

Rich 发送、编辑和草稿复用 SDK 请求配置及原有投递队列。定稿重试复用已经送达的原生分段 ID；已明确不支持新接口的本地 Bot API 使用完整旧格式回退，限流与网络失败继续按原有规则重试，不另发旧格式消息。

验证包括模拟 Bot API 10.3 的多轮成功／停止／失败链路、三种回复方式、长文、宽表、HTML 安全、原文不变、过期草稿、断线补发、重复定稿和旧 API 回退。这里的测试使用隔离数据库与模拟 Telegram，不向真实聊天发送测试消息。原生显示以支持 Rich 的 Telegram 客户端和 Bot API 为运行前提。

## 表单入口调整

独立 Mini App 表单已撤回。`ask-x` 使用原生选项和电报文本录入，成功后清理录入消息与提示；普通浏览器中的内嵌表单继续与电报共享状态。没有 HTTPS 地址或没有启用 Web 不影响 Bot 表单。

## 第三阶段：电报独立会话页面

在 BotFather 开启私聊话题后，启动时给现有未归档会话建立页面映射，新建会话也建立自己的页面。旧 Telegram 消息留在原处，不搬移、不补发；应用会话历史和当前模型上下文保留。

页面内的输入先绑定应用会话，A、B 可以独立执行；回复、命令、草稿和文件使用捕获的页面地址，中途切换不改投已开始的回合。页面自身的创建、改名和开关事件不当成用户聊天。应用重命名、归档和恢复同步对应页面，删除应用会话不删除 Telegram 消息。

创建页面的网络结果不确定时保存待确认状态，不重复创建；`/topics` 查看会话和页面 ID，`/topic_bind 会话ID 页面ID` 绑定已有页面。尚未绑定的目标不改投其他页面，原消息仍留在应用历史。

数据库启动前备份并迁移到 schema v9，映射纳入会话备份。恢复或换 Bot 时以 Bot 身份匹配映射，不复用另一台 Bot 的页面 ID。测试覆盖 v8 迁移备份、现有会话、A/B 同时执行、固定回复路由、重命名归档恢复、创建结果未确认及换 Bot。

## 原生按钮与入口精简

短文本原生复制、媒体类型投递、`/stop`、授权用户的 Inline 搜索继续保留。独立阅读、设置、任务和文件网页、签名下载和网页分享、扫码、桌面入口及 Telegram 设备草稿已移除。原浏览器工作台和下载保持原有接口。电报网页入口只保留 `/start → Web配置 → 打开网页版`，左下角恢复命令菜单。
