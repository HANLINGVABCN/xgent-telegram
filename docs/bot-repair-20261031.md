# Bot 精简、思考展示与资源修复

移除独立表单、阅读、设置、任务和文件 Mini App，以及分享、扫码、桌面入口、设备草稿与对应专用路由。网页入口仅保留 `/start → Web配置 → 打开网页版`，电报左下角恢复命令菜单。普通浏览器工作台、内嵌表单、文件和终端继续使用原接口，Cloudflare 邮箱验证无需调整。

协议使用合法的原生可展开引用，内部采用行内格式内容，不将独立 `<pre>` 嵌入仅接收 RichText 的可折叠引用。保留50行／3200字符工具预览、协议标识、真实状态和末尾存档；最终多轮回复只附一次详情。

`ask-x` 回到原生选项与文本录入。填入字段后原表单显示答案及对号，成功保存和重绘后删除录入回复与提示；字段 cancel 不影响其他答案。密钥不回显、不存入普通草稿或聊天。浏览器和电报仍共用表单状态，进程重启后的挂起执行恢复继续单独处理。

Web 思考内容只来自提供商可见字段，与正文、工具和下一轮模型输入分离。两种流式均显示当前最新行；结束自动收起，仅留状态与接收阶段的估计耗时。非流式未提供明确独立耗时则显示“耗时未记录”，没有思考文字的历史不显示空块。签名及加密内容不作为思考文字。

生图内部使用独立媒体列表，原生字段不再拼成正文后反向解析。旧式媒体返回仍可保存，解释中的编码示例不会作为图片。不同原图保留、相同内容不重复保存。Web多图两列排列，路径用小字，文字在全部图片下面；Telegram优先使用一条Rich媒体消息，旧接口使用相册，超限安全续段。没有公开图片服务器也能通过现有SDK上传。

待发取消被明确拒绝时清理残留；网络结果未知时按请求ID核对，取回内容只回填一次。撤回读取全部原生分段关联和同进程逻辑ID，跨进程不复用旧逻辑编号。新发送补记实际Telegram ID，撤回后的已知记录不再补投。

`grep-x`与范围读取使用独立、可中止的读取进程，64KB分块，16MB单行／片段上限。默认目录检索排除数据库、二进制和运行数据，明确指定日志文件或日志过滤条件可流式检索。取消会终止读取进程，正则和大文件处理不再阻塞应用退出。

全量trace在序列化前移除媒体编码，记录长度和指纹；文件10MB轮转、保留5份备份，队列额外限制8MB。保留动态内存保护，停机先处理活动回合和后台生产者，再关闭Telegram请求。非Git更新包从归档根名记录提交标识，安装日期不能当作最新提交证明。

测试使用隔离数据库、模拟Bot API与本机Chromium，不向真实Telegram聊天发送测试，不修改或重启服务器。600MB模拟日志测试验证读取内存与取消边界；实际Telegram客户端折叠效果仍需要更新后的用户端体验验收，不能用模拟结果替代。
