# Web Agent 工作台改版说明

## Telegram 风格输入区命令列表

- 点击输入框左侧菜单，在输入框正上方展开可滚动的命令列表；不再用命令弹窗、侧栏或全屏遮罩，不锁定聊天区域。命令名与说明并列，`/start` 第一项，选择普通命令直接执行一次。
- 再点菜单、点列表外或按 Esc 收起；打开/关闭不改草稿，触屏打开时不抢输入焦点、不主动弹软键盘。列表高度按当前输入区和可视高度计算，桌面支持方向键、Home/End 和 Enter。
- 顶部菜单及 Ctrl/Cmd+K 复用输入区列表；从管理页进入先遵循未保存表单离开确认。清空、重启等危险命令仍保留单独确认，退出登录行为不变。
- 保留前版无管理页依赖的事件绑定、真实注册表、失败提示和手动重试；关闭列表后取消加载，迟到响应不会重新打开列表。


## 基础按钮不再依赖管理页初始化

- 菜单和退出登录的点击绑定、请求、错误反馈及基础弹窗移到无管理模块依赖的聊天入口。工作台正常初始化后仅接入表单未保存提示等增强能力，不再重复绑定按钮。
- 设置与用量脚本仅在进入对应页面时加载；用量脚本 404、依赖加载失败或工作台解析异常不会连带禁用菜单和退出。页面默认保留可用聊天布局，避免可选模块失败时连输入框都隐藏。
- 基础操作请求超过 12 秒显示超时提示，提供明确的手动重试，不自动重试命令或退出请求；使用真实后端命令注册表。浏览器拒绝读写偏好存储时，基础聊天操作仍可初始化。
- 验证新增真实触屏点击回归，故障注入覆盖工作台/依赖 404、解析错误、禁止浏览器存储、独立管理页失败、请求超时及退出失败重试。此类故障之前只在完整资源加载成功的环境中验收，未覆盖依赖失败。


## 菜单、退出登录与详细用量报表

- 顶部、输入框左侧和导航的菜单入口统一打开工作台命令中心，不再分别打开旧侧栏与新弹窗。命令尚未加载时显示加载/失败/重试，生成、断线或待上传附件阻止执行时说明原因且不覆盖草稿。
- 顶部、命令菜单和设置首页提供退出登录入口；退出清理当前页面的消息、草稿和实时连接，返回登录界面而不刷新页面自动触发 Telegram 免密登录。服务器后台任务不因退出而取消。
- 时间范围合并为最近 7/30/90 天、全部、自定义一组选择。起止日期始终显示，预设为只读；自定义在原位编辑并应用。显示实际时间和调度时区，自定义结束日期包含当天，全部覆盖最早一条用量记录至当前时间，不受一年限制。
- 参照 Token HTML 报表补齐调用、缓存、思考、总量、费用、单次均费、缓存节省；模型表展示占比、原始名称、合并结果与三项单价，调用明细展示缓存、思考和逐条估算费用。趋势与模型分布支持 Token/费用切换，模型表可排序，明细按 50 条增量加载。
- 计费及模型合并复用现有报表规则；缺失价格显示“未配置”，不伪装成免费。跨年范围按月绘图，汇总仍覆盖全部记录；原始明细留在服务器 SQL 分页，不把全部调用下载到浏览器。


## 已存盘回复的呈现一致性

- 修正协议折叠关闭时实时回复走服务端 HTML、历史却重新走浏览器 Markdown 的差异；生成媒体正文也使用相同的显示转换。
- 新保存的 AI 回复在元数据中保留完整显示快照，原始 `content` 和 AI 上下文不改写。已有显示元数据继续优先使用；没有快照的旧记录由同源渲染器兼容读取，不批量改写旧历史。
- 定稿后仅发送这一条已存盘回复的快照，将 Telegram 长消息分段合并为网页上的完整回复，并携带全部分段 ID。Telegram 的发送与长度限制不变；不额外拉取全量历史，不对其他消息重新排版。
- 历史首屏、翻页和实时定稿共用消息角色、正文、时间、附件和身份合并路径；已定稿气泡不被迟到的临时分段覆盖。相同内容的编辑不重建正文，避免已展开协议块无故收起。
- 实时标准错误提示按字面诊断代码块显示，与存盘版本一致；原有报错 50 行永久省略规则保持不变。
- 回归使用三种真实回复模式（非流式、前台流式、后台流式）× 折叠开/关，逐一比较实时定稿、刷新和历史翻页的 DOM；包含长回复分段、表格、代码、90 行协议块、错误和生成媒体，不调用真实模型。


## Trigger 与技能管理细节优化

- 任务支持服务端按名称、命令或 ID 搜索，叠加状态和触发方式筛选；SQL 分页固定每页 50 项，显示总数、上一页/下一页及全局状态概览。同一创建时间按 ID 稳定排序；筛选后页码越界自动回到有效页。
- 列表直接显示执行规则、条件、下次执行和失败次数；运行时间按任务时区显示。补齐“等待通知”状态，不把已经结束的任务旧时间误显示为下次执行。
- 可全选本页未结束任务、逐项或批量取消。完成/失败/取消的任务不可勾选，取消前说明三端共享影响，详情内取消后重新读取真实状态；输出存档可返回任务详情。
- 创建表单切换延时/指定时间/Cron/条件时保留各自输入和统一时区，提供常用时间与 Cron 快填；预览不创建任务，仍使用原调度器校验及请求标识防重。
- 技能卡片外层直接提供“启用 / 关闭 / 隐藏”，点击即保存，不必先开详情再点保存。正在保存时禁用重复点击；失败保留原状态并在卡片内说明，不自动重试写请求。
- 技能名称/路径、状态、来源在当前列表本地筛选，不为每次输入重复请求；显示匹配数量和启用数量。详情专注于完整说明和复制。
- 手机任务列表使用可纵向阅读的卡片布局，技能筛选分行、触控按钮不小于 44px；切换筛选时保留原列表直到新结果返回，避免整页加载闪烁。表单提交期间锁定输入，避免请求中的内容被改写。
- 验证使用临时数据库和未启动调度器的隔离数据，新增管理回归与 390/768/1440 明暗主题截图；不接触生产任务或真实模型。


## 这次改了什么

- 从单聊天页升级为六个功能区：对话、任务、文件与输出、模型与技能、用量、设置。
- 桌面左侧导航、按需详情区；手机底部导航、单栏表单与全屏详情。明暗主题、键盘导航、减少动效、草稿保留。
- 提供商完整管理、只写密钥、候选模型筛选、对话/媒体模型指定、配置导入及脱敏/含密钥导出；选择状态刷新和跨端重载保持一致。
- 延时、指定时间、cron、条件触发各有对应表单，明确时区和执行影响。任务创建使用持久请求标识去重，详情可查看/分页执行记录和取消任务。
- 关联文件可预览、下载和定位来源；文本附件及命令存档按页读取，避免一次性载入大文件。不能浏览或读取任意服务器目录。
- 历史首次读取 50 条，双向游标分页，服务端搜索可定位尚未加载的记录。分别限制两个索引数据源后再合并，处理相同时间戳和 UI 修订/删除。普通消息约 200 条的显示窗口，保留正在选取或展开的内容。
- 设置分组管理，不再把常用管理操作藏在聊天菜单；新增 Web 开关、端口及公开地址表单、密码修改和独立健康详情。
- 用量 SQL 汇总全部选定范围，复用价格和模型合并规则；未定价不是零费用，调用明细支持分页。
- 网页终端支持标签、会话切换、断线重连、输入顺序、关闭确认及失效状态。一个 PTY 只有一个输出读取器，客户端使用独立游标，不再互相抢输出。

## 部署与兼容

无需 npm 或构建。部署时更新整个仓库（包括 `xgent_app/webui/assets/`），重启现有服务即可；不要只复制 `index.html`。静态资源采用白名单、正确 MIME、ETag 和重新验证，避免旧脚本长期缓存。

管理接口集中在 `/api/workbench/`，继续使用既有认证和同源校验。数据库只新增显示查询索引及任务请求去重表，不删除历史、不改共享记忆语义。原 `/`、`/terminal`、旧 API、Telegram/CLI 菜单和消息渲染兼容。

本次不加入 Termux 输入法切换模式，不改变 TUI 的现有鼠标行为。Telegram 展示限长仍仅在 Telegram 出口处理；Web/TUI 完整展开和日志资源保护保留。

## 安全与边界

- API Key 普通读取不回传明文，编辑留空保留；清除和含密钥导出需明确选择。密码和密钥表单不存浏览器持久存储。
- 任务和终端拥有运行账号的真实执行权限，本改版不是沙箱。查看文件/日志不会执行其中的脚本或协议。
- 真实 PTY 仅支持 Linux/Unix；Windows 明确显示不可用。最多 3 个会话，30 分钟无输入输出回收；每会话仅保留 2 MiB 重连输出，超出窗口提示缺口，不承诺终端画面无限回放。
- 服务重启和改密后会话失效，不自动新建 Shell 或重新运行旧命令。
- 旧内容若已经被截断且未保存原文/存档，无法凭空恢复；大存档原有大小上限仍有效。

## 后续修复：命令解析和页面切换

- 修复工作台初始化把未保存的配置写成 `None`，导致 Agent 在模型回复后解析命令时报 `int(None)` 的回归。缺失记录不覆盖运行默认值；`smart_match_threshold` 启动时加载并归一化，空值/损坏值回退 90，明确的 0 保留。验证覆盖打开网页后解析、执行三条只读命令、存档及记录历史。
- 工作台切换页面优先恢复内存缓存中的原 DOM 和滚动位置，不再每次清屏等待网络。按页面期限后台刷新，写入按依赖使缓存失效；读接口、导出、拉取候选模型不会无故使其他页失效。
- 缓存最多 12 个页面，仅驻留当前标签页内存；退出或认证失效时清空，不缓存密钥表单和 API 密钥。
- 后台响应在页面切换、并发写入或开始编辑后不替换用户正在操作的内容。旧内容刷新失败仍可读，并有重试提示；已勾选任务、输入焦点和文本选择得到保护。
- 浏览器回归覆盖慢网、快速来回切换、过期缓存、跨客户端配置修改、操作失败、弃用表单、筛选状态和手机导航。


## 刷新与实时状态修复

- 事件队列之外单独保存有界的“正在处理消息”最新快照；读取快照不消费其他浏览器的数据，旧事件被淘汰也不会丢失正在生成的占位消息。
- 历史请求先获取快照游标，再读取数据库；浏览器补收游标之后的事件，避免刷新与流式编辑之间的空窗。最终回复保存显示消息 ID 与事件 epoch，仅同一服务实例内关联，避免重启后的 ID 复用误合并。
- SSE 建立不再触发第二次历史重载，回合完成不再清空消息列表。相同内容保留原 DOM、滚动和选区；真正发生编辑/删除时原位更新。
- 降级为长轮询时，有消息立即唤醒连接，无固定轮询间隔；认证失效和服务关闭会结束等待。
- 管理页缓存后台检查只有数据变化时才更新界面；响应内容相同不再周期性重建或显示加载提示。首次访问仍需获取一次数据，不承诺无网络条件下获得服务器状态。
- 当前生成快照最多 64 条/8 MiB，只用于显示，不进入模型上下文；服务重启后不存在运行中的旧生成请求，不能伪造恢复它。数据库最终记录、报错永久五十行规则不变。
